# 剧诗规则、巡演原石目标与整局决策节点：研究结论

研究日期：2026-09-17。对应[核实剧诗规则、原石奖励目标与整局决策节点](https://github.com/HaotongCheng/BetterTheater/issues/2)，承接[采集所选期次的奖励页与局内状态转移证据：取证交付](https://github.com/HaotongCheng/BetterTheater/issues/9#issuecomment-5721059216)。本文是可独立阅读的最终综合报告，替代前两轮报告中“必须补全客户端截图后才能完成研究”的结论；前期材料仍保留为调查历史。本文不选择算法、首版交互或验收门槛。

## 结论与适用范围

**本次有界研究可以完成。** 已厘清周期原石目标、角色与资源的主要约束、局前到终幕的决策节点，以及通用规则、版本规则、每期配置和实际观察之间的边界。完整事件价格、随机分布和字段级回溯语义仍未知；这些未知不妨碍说明整局问题，也不等于已具备精确模拟整局的规则库。

本轮目标是当期全部**巡演原石**：主线十幕共 800，两个圣牌奖励档各 100，合计 1000。圣牌奖励须完成相应挑战并通过第十幕；明星条件及星章奖励与此分开。一次性初演馈赠已由用户排除。完整逐幕数字采用用户明确接受的 BWIKI 通用奖励表；月谕新增档位和附加条件由官方图交叉核对。不能把这个来源组合表述为“已逐页实测北美服 7.0 全部奖励”。[W1][O2][E1]

实测样本定位为用户自述的**北美服、2026 年 9 月期、7.0**。主线已通关并领取 800 原石，两场圣牌均尝试而未通过，故记录为 **800/1000**，目标未达成。本局未使用回溯；没有失败后全部字段的配对观察，也没有完整逐幕账本。样本能说明这些节点实际出现，不能证明推荐有效或可以免除人工纠错。[E1][E2]

## 原石档位与完成条件

下表是 W1「奖励」表的事实摘要；主线小计为逐幕相加。O2 独立证实新增巡演 200、初演 300，以及圣牌巡演档位需要第十幕完成的条件。

| 档位 | 巡演原石 | 初演原石：仅作区分，不纳入目标 |
|---|---:|---:|
| 第 1、2、4、5、7 幕，各幕 | 60 | 100 |
| 第 3、6 幕，各幕 | 100 | 200 |
| 第 8 幕 | 120 | 200 |
| 第 9 幕 | 60 | 150 |
| 第 10 幕 | 120 | 250 |
| 两个圣牌档位，各档 | 100 | 150 |
| 主线小计 | **800** | 1500 |
| 含两个圣牌合计 | **1000** | 1800 |

主线档位按对应幕次完成领取；圣牌的官方脚注是：通过第十幕后，可领取**每个已完成圣牌挑战**的对应奖励。两张均完成是拿满圣牌 200 的条件，不能把收藏卡的“完成全部”条件反推成只完成一张也不能领取其对应 100。W1 所列 3、6、9、12 星章档均为非原石；O2 单独确认新增 12 星章档为祝圣之霜。因此本研究中的周期原石目标不要求满星，亦不把获取收藏卡或材料奖励并入目标。[W1][O1][O2]

“通过战斗”“取得星章”“圣牌完成”“奖励已领取”是四种事实。样本的战车基础条件为限时击败强敌，65 秒是明星条件；月亮基础条件为坚持到倒计时结束，击败 18 名敌人是明星条件。用户确认两张都是基础挑战失败，分别为超时和角色倒下；“伤害不足”“心海治疗量不足”是用户归因，未由完整阵容、配装和战斗过程独立验证。[E1][E2]

## 已确认的规则与随机过程边界

**准入与角色流转。** 月谕官方要求先通关卓越，28 名起、可多带 4 名、等级 70，可邀请 1 名助演。[O1][O2] BWIKI 补充：开幕六人先可出战，待命需经招募加入；基本规则为四人出战、初始各两点耐力、完成战斗扣一点，并存在恢复或返场事件。它还明确助演不计入准入人数，故“名单可借一人”不能直接解释为“借一人补足准入门槛”。这是社区通用说明，未在本局单独测准入边界。[W1]

**圣牌时机与失败。** 消耗一定耐力后出现圣牌事件，至多同时两个；官方未给精确阈值。可在第十幕前选时机与阵容，进入前能预览挑战。失败不耗耐力，可重复尝试或返回事件队列。这里明确的是耐力和重试权限，不是全部资源、生命、能量或随机候选严格不变，也不是演出回溯。[O1]

**招募不是所有节点都一样。** 卓越、月谕的强敌战后改为三选一；月谕还覆盖圣牌挑战后与角色事件。强敌有元素弱点时，对应伙伴事件在强敌战前保证出现。保证的是事件类别，不是指定角色，也不证明候选均匀抽样。第一幕前可选择升级多类辉彩祝福或集中一类；实际操作仍受当前选项与资源约束。[O3]

**花朵、祝福与刷新。** 样本提供四类对照：招募后可出战人数 7→8；绽放 0→1、花朵 145→85；普通战成功后四名角色耐力 2→1，花朵 85→175；第九幕刷新次数 1→0，事件候选改变，两张圣牌入口仍在。刷新后花朵被裁掉，不能从该对照判定刷新免费。60 的购买成本和 90 的收入是该事件实测，不是全部版本通用常数。[E1]

**随机性的研究清单。** 应区分事件生成、招募候选、选择后随机效果、恢复耐力的目标，以及玩家可见后的选择；还要区分保证出现规则与随机抽取规则。这一分层是从 O3、W1 和 E1 推导的研究描述，并非算法方案。W1 有修改价格、候选、收入或耐力的词条，同时混有旧系统条目；不能直接当作 7.0 完整可出现事件表。没有得到完整现行概率分布；少数词条自带概率也不能推广到其余事件。[O3][W1][E1]

**回溯。** BWIKI 描述回到上一首领战后的记录点，恢复角色及多类增益、撤销后续挑战记录；前轮官方核对仅能支持 5.0 非轻简模式的历史次数调整。花朵、候选是否重抽、圣牌出现或完成标记如何恢复，以及当前月谕的全部次数规则，尚无字段级证据。本局没有使用回溯，故本局对照是“不适用”，不能用普通失败重试代替。[W1][H1][E1]

## 整局状态与决策节点清单

下表是上述证据支持的**问题分解**，用于后续讨论；不是要求首版保存全部字段，更不是已选技术接口。角色练度和实际队伍能力沿用项目已有区分，不能把拥有角色或官方定位标签直接等同于足以通过某场挑战。

| 节点 | 决策所涉及的状态或约束 | 玩家能够作出的决定；必须区分的结果 |
|---|---|---|
| 期次与目标 | 服务器、版本、期次、模式；巡演档位、完成条件、领取情况 | 选可进入的模式及本期目标；准入不足与奖励已拿满不同 [O2][E1] |
| 局前参演和借用 | 自有角色池、练度、元素与等级资格、开幕试用、特邀、实际可借对象 | 选参演与助演，形成最初预留；准入计数和最终名单分开 [O2][W1] |
| 第一幕前准备 | 初始可出战与备用角色、花朵、可见事件、祝福 | 招募或升级、集中或分散祝福；用实际结果更新 [O3][E1] |
| 幕间购买与刷新 | 幕次、花朵、价格、剩余刷新、候选、既有增益及其期限 | 买角色、买祝福、其他事件、刷新或开战；推荐动作不等于已执行 [E1][E2] |
| 招募结果 | 实际候选、节点类型、当前可出战与备用名单 | 从真实候选选择；模式例外及事件效果可能改变候选范围 [O3][W1] |
| 普通战与强敌战 | 敌人、基本条件、明星条件、舞台效果、可用队伍、剩余耐力、后续已知战斗 | 选阵容和预留；战后分别确认胜败、耐力、花朵、招募与星章 [E1][E2] |
| 圣牌出现与挑战 | 两张各自是否出现、条件、完成状态；当前阵容和剩余主线 | 现在打、调整后重试或延后；第十幕前有明确截止点 [O1][E1] |
| 失败、回溯或重开 | 操作种类、实际返回位置、可见角色/资源/增益/候选 | 失败重试、回溯、重开分别处理；未观测恢复字段保持未知 [O1][H1][E1] |
| 第十幕与结算 | 剩余圣牌、当前奖励缺口、主线完成、各档领取 | 决定是否进入终幕；结算后逐项判断目标，不能只看“演出成功” [O1][O2][E1] |

需要分别表达的资源包括花朵、角色可出战次数（耐力）、刷新次数及有时效的增益；奖励进度是结果状态。未来敌人需求、角色协同及玩家操作经验会影响分配，但本文不把它们压成单一强度分数，也不据样本推荐固定保留某名角色到某幕。

| 层次 | 内容 | 本次结论 |
|---|---|---|
| 长期业务概念 | 角色来源、准入、参演与可出战状态、资源、挑战条件、奖励领取 | 可用于组织讨论；“长期”不代表官方承诺永不改变 |

| 每期配置 | 三元素、开幕与特邀、祝福、敌人和挑战条件 | O4 给出 2026-09 元素水/雷/草；开幕 Columbina、Xingqiu、Cyno、Kuki Shinobu、Lauma、Kaveh；特邀 Odette、Sandrone、Sucrose、Nicole。保留来源英文名，不将未核对译名当官方中文 |

## 已知未知与研究完成判断

| 仍未知或未完整核验 | 对当前结论的限制 |
|---|---|
| 全部现行事件、基础成本及折扣叠加 | 不能自动推算任意事件的最终价格；代表性实测价格不外推 |
| 完整随机分布、候选相关性、重抽机制 | 不能宣称精确成功概率或最优解；不默认等概率或独立 |
| 圣牌精确触发阈值与本局首次出现节点 | 记录已出现的事实，不强行补某幕/某耐力阈值 |
| 回溯的字段级恢复语义及当前月谕次数 | 不能精确模拟回溯；本局未使用，不制造缺少用户材料的任务 |
| 圣牌失败后的全部本局状态 | 用户未留意；官方“不耗耐力”不能变成全部字段实测不变 |
| 7.0 全补丁差异、9 月完整敌人与祝福数值 | 本文不是完整当前规则数据库；不用滞后的“当期”页填空 |
| 完整逐幕账、失败次数、总耗时、因果归因 | 不能计算可靠效率、通关提升或把失败单因归到某角色 |

这些边界已显式记录，**不再转成补截图、刻意触发回溯或重打一局的默认要求**。本研究的问题可以在此范围内解决；若后续方案确实依赖精确价格、随机分布或回溯预测，再由该方案提出明确的验证需求。角色能力表达、最小状态与纠错负担、首版决策闭环分别留给[决定怎样描述角色与队伍的实际可用能力](https://github.com/HaotongCheng/BetterTheater/issues/5)、[决定局前到局内的最小状态与纠错负担](https://github.com/HaotongCheng/BetterTheater/issues/6)、[选择首版决策闭环与建议呈现方式](https://github.com/HaotongCheng/BetterTheater/issues/7)。报告没有代替这些产品决定。
