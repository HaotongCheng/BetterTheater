# 当期规则包：版本管理与标题匹配原型的证据与建议

日期：2026-10-01。对应 [验证当期规则包的版本管理与标题匹配](https://github.com/HaotongCheng/BetterTheater/issues/17)。原型代码在 [`prototypes/rulepack-title-matching`](../../prototypes/rulepack-title-matching)（分支 `prototype/rulepack-title-matching`），是可抛弃的决策材料，不是产品架构。输入是 [核实当期祝福与神秘礼物的预备资料和标题匹配边界](https://github.com/HaotongCheng/BetterTheater/issues/13) 的结论。

## 一句话结论

**建议把“当期规则资料”做成带来源与核验状态的规则包：规则身份 = `规则集 / 反应族 / 等级 / 分支路径`（神秘收获 = `规则集 / 标题`），标题与文字只作证据；匹配按“标题精确命中 → 反应族/等级一致 → 摘要覆盖率校验 → 多候选用区分性文字定路径”四步走，任何一步对不上就输出“多候选 / 未知 / 矛盾”，不按相似度套用；换期靠“导入 → 结构校验 → 逐条客户端核验 → 发布；再导入 → 按身份 diff → 变化条目核验失效”闭环。** 以上在 24 个用例上全部成立，但真实画面只有 4 张，其余输入是合成的。

## 证据边界（先读这一段）

- **真实样本只有 4 张截图**（#13 报告登记的 G1–G4：局前绽放树预览、激化·原态获得页、神秘收获持有页、祝福汇总页）。它们核验了 5 个条目：3 个祝福节点、2 条神秘收获；其余 240 条全是候选。
- **没有 2/3/4 级的汇总页或获得结果页真实样本**。场景 4、6、7、9、10 的输入是合成的，只用来暴露边界；“3 级汇总是否显示父分支的额外效果”是本原型最关键的未验证假设。
- **阈值**（整体覆盖率 35%；区分性覆盖率 30%、领先 25 点）在这 24 个用例上调过，没有留出集。
- **没有接 OCR**：输入是人工抄录的画面文字。OCR 误读在本原型里会表现为“未知 / 矛盾”；原型只保证不静默套用，不保证召回。
- **BWIKI 快照**是 2026-09-17 的社区页面（revision 674516，CC BY-NC-SA 4.0），不是官方注册表；“当期三族”来自官方 7.0 更新说明；神秘收获的 7.0 可出现全集仍未证明。
- **神秘收获生命周期**（本幕内 / 持续 / 一次性 / 限次 / 条件触发）是人工从条文推断的标注，只标了 10 条；其余显示“未标注”。

## 规则包长什么样（导入结果）

| 项目 | 数字 | 说明 |
|---|---|---|
| 规则集 | 4 | `current`（现行表）+ `legacy-pre-2026-02 / -03 / -04`（“加强历史”里的旧表，只含被调整的反应族，不是完整期次快照） |
| 祝福树 / 节点 | 23 棵 / 207 | 现行表 18 族 + 旧表 5 族；每棵 9 个节点：原态 1、初阶 2、**进阶 2**（按父分支各一个）、极限 4 |
| 神秘收获 | 38 | 伙伴 15、惊喜 14、助益 7、礼物 2；标题在快照内无重名 |
| 已核验条目 | 5 / 245 | 只登记画面上直接看到的字段（标题 / 完整文字 / 简要文字） |
| 疑似旧系统词条 | 7 | “助益·”全部，条文仍写“奇妙助益”；是否还会在 7.0 出现需核验 |

每个条目带：`id`、`ruleset_id`、`title`、`text`、`text_hash`、`in_period`、`verification{status, verified_text_hash, evidence, verified_fields}`；祝福节点另带 `family / level / path / parent_id`。规则包带来源 revision、SHA-256、抓取日期、导入时间、清洗规则和声明范围（服务器 / 客户端版本 / 期次 / 语言）。声明范围是声明，核验状态在条目上。

校验器从这份数据里直接报出来的事实：

- 同一规则集内**同名不同路径**的末级节点 4 组：蒸发·极限原态（1B/2B）、融化·极限禁绝（1A/2A）、雷晶·极限崩落（1A/2A）、雷晶·极限霰石（1B/2B）。四组都是**文字也相同**，差别只在继承的 2 级分支。
- 每个反应族的 **“X·进阶”有两个同名同文节点**，游戏内树（G1）也确实两侧各画一个。
- **跨规则集同名 37 个标题**，其中 23 个文字有变化、3 个左右位置换过（火晶·初阶岩破、火晶·极限瓦解、火晶·极限碎岩）。“火晶·初阶迸火”只在旧表有。

## 匹配规则

1. **标题精确命中**（归一化“·”与空白）。命不中：若其他规则集里有 → “矛盾：版本漂移”；都没有 → “未知”，相近标题（Dice 相似度）只作提示，不自动采用。
2. **反应族、等级一致性**。不一致 → “矛盾”。等级 0 → “未解锁”，不对应节点。
3. 有摘要时算**整体覆盖率**：画面文字的二字片段有多少出现在“候选节点及其祖先”的文字里（去掉数字、单位、标点和“体系增强 / 额外效果”等页面标签词）。最高也低于 35% → “矛盾：文字不符”。
4. 仍多候选时只看**区分性片段**（不是所有候选共有的那部分）；领先者覆盖率 ≥ 30% 且领先 ≥ 25 点 → 命中，否则 → “多候选”。

输出四态：**已匹配**（带身份、继承的祖先、核验状态）/ **多候选** / **未知** / **矛盾**（版本漂移、等级不符、反应族不符、文字不符）。

## 导入、校验、核验、更新：最小流程比较

### 资料来源

| 来源 | 能提供什么 | 不能提供什么 | 成本 / 更新触发 |
|---|---|---|---|
| BWIKI 快照（本原型） | 全部反应族的树形、标题、完整文字、历史旧表、神秘收获候选表；表形规则，脚本可解析 | 官方权威、稳定 ID、当期可出现全集、神秘收获是否仍启用 | 一次抓取 + 脚本；页面改版会让解析失败（会报错不会静默） |
| 游戏内局前树预览截图（G1 类） | 当期客户端的树形、标题、完整文字，第一方 | 神秘收获目录；需要逐屏截图、OCR 或人工抄录 | 每期一次人工操作；是**核验**来源而非导入来源 |
| 官方更新说明（O1–O4） | 期次元素、“有变更”的信号 | 完整目录与文字 | 每版本读一次；只当**换期触发器** |
| 手工录入 JSON | 任意结构 | 可追溯性、重复劳动 | 每期全量重做，易漏 |

### 最小闭环（本原型跑通的部分打 ✔）

1. ✔ **抓取并固定来源**：保存 HTML、记录 revision、SHA-256、日期。
2. ✔ **导入成候选包**：按表形解析；所有条目 `candidate`；清洗规则写进包里。
3. ✔ **结构校验**：身份唯一、树形完整、父子路径一致、神秘收获标题唯一；同名报告。
4. ✔（5 条）**逐条客户端核验**：对照当期截图，登记到 `verification.json`，只登记看得见的字段；未核验条目不得发布为“可出现”。
5. ✔ **发布**：规则包带声明范围 + 来源 + 核验状态。
6. ✔（合成）**换期**：官方公告触发 → 重新抓取导入 → 按身份 diff → 新增/删除/改名/改文字的条目回到候选，已核验的标“核验失效” → 重新核验。

### 被否定的做法

- **标题即 ID 的扁平表**：被 4 组同名不同路径、18 组“进阶”、37 个历史重名直接否定。
- **无版本的 JSON 一直沿用**：被 O2–O4 的官方变更和火晶新旧表（同标题、换位置、改文字）否定。
- **模糊相似度自动套用**：被场景 7 否定（碎霆 / 雷暴同为 86%）；“未知 / 矛盾”必须是一等输出。

## 对后续实现的事实输入

- 规则身份与存储形状如上；局内读取必须保存**路径**（或能推出路径的获得历史），只存“激化 2 级”会丢决策信息。
- 匹配输出四态；上游 OCR 的误读会落到“未知 / 矛盾”，由人工纠正或重读，不由匹配层猜。
- 神秘收获实例 = 规则身份 + 实例参数 + 获得幕次 + 状态；**持有列表只能核对“有没有”**，不能推断层数、剩余次数、是否已触发，也不能假定游戏会移除已结束项。
- 等级误读文字抓不住：等级要靠 OCR 的数字校验（#15 路线里的词表/范围约束）或获得事件序列校验。
- 规则包 diff 与核验失效是换期安全网；文字相似度不是（旧文字对改过数值的新文字仍有 90% 覆盖）。
- BWIKI 的“加强历史”是按反应族的片段，不是整期快照；产品规则包应按期次整包存档。

## 需要用户反馈的问题（待用户定）

1. 规则身份用 `规则集 / 反应族 / 等级 / 路径`，“进阶”按父分支拆成两个节点——是否接受？
2. 3 级汇总页是否显示 2 级“额外效果”行？4 级获得结果页标题是否就是末级节点名？这两点决定 3/4 级能否只靠画面定身份，需要截图（#13 报告的验证 2、3）。
3. 当期三族（绽放 / 激化 / 感电）没有同名反例；同名不同路径只在蒸发 / 融化 / 雷晶上验证——是否接受，不再为当期专门取证？
4. 神秘收获：持有列表是否移除已结束 / 已消费项？随机目标是否显示在卡片上？是否需要一张“触发前后”配对截图？
5. 首版资料流程是否接受“BWIKI 快照导入 + 人工核验登记 + 官方公告作换期触发器”？“助益·”7 条是剔除还是保留为候选？
6. “对不上就报未知 / 矛盾，不做模糊套用，由人工纠正”——是否接受为匹配层的约定？

本报告不把原型结果解释为规则包已覆盖当期全集，也不解释为识别链路已能从真实画面读出这些字段。
