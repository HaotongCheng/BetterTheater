# 账号与实际可借角色数据：获取边界

研究日期：2026-09-17。对应 [问题 #4](https://github.com/HaotongCheng/BetterTheater/issues/4)。服务目标是本人先用、结合实际角色池与练度规划剧诗，以更少重试拿全原石奖励；本报告不决定架构或推荐算法。

## 结论

已有开源实现支持从米游社/HoYoLAB 战绩接口读取拥有角色列表及详细配装，值得作为本人授权后的候选数据来源。公开 UID 查询 Enka 只能解决公开展示角色，不能据此补全整个账号。两者都没有在本次检查中证明能列出“这个账号现在真正可借的好友助演角色”。因此账号配装与可借资格必须分开记录，后者暂以用户在游戏内看到并确认的名单补充。[S1][S2][S5][S7]

这是源码和服务文档审计，不是上线可用性验收。本次没有登录米游社/HoYoLAB、提取游戏凭据、查询私人账号，也没有调用角色私有接口。实现存在不等于服务端今天对每个地区、账号和字段均成功返回。

## 来源和覆盖矩阵

| 来源 | 范围 | 中国服 / 国际服 | 身份与权限 | 主要边界 |
|---|---|---|---|---|
| genshin.py → 米游社战绩接口 | 实现先获取拥有角色 ID，再获取详情；本人数据是目标路径 | 源码有中国服路由，并识别天空岛、世界树 | 需要对应服务登录会话；不是仅凭游戏 UID | 中国服实际授权及完整性未实测；不能保证渠道服账号均成功 |
| genshin.py → HoYoLAB 战绩接口 | 同一列表→详情流程 | 国际服有独立路由，识别美、欧、亚、港澳台 | 登录 cookies；访问本人和别人不是相同权限 | 他人公开设置及服务限制影响返回；不能承诺任意 UID 全角色 |
| Enka UID | 当前角色展柜的角色详情 | 已确认通用 UID 接口；本次没有找到足够的一手支持矩阵确认各中国服覆盖，须逐服验证 | 公开 UID，不需要游戏登录；展柜必须有可见详情 | 不是全拥有角色；关闭详情或空展柜会缺少 avatarInfoList |
| Enka 保存配装 | 用户主动保存/刷新的配装快照 | 继承上游账号限制 | 公开已验证 Enka 账号可被查询 | `live` 也只是用户最近刷新时的结果，不自动实时同步 |
| 用户游戏内核对/截图 | 本人当前看到的角色及助演候选 | 不依赖第三方 API 覆盖，但界面需确认 | 用户本人操作 | 仅画面明确显示的字段可靠；本次未拿截图，OCR 准确性未验证 |

前三项的实现和权限依据见 [S1][S3][S4][S5][S6]。中国服与国际服登录体系不可视为同一凭据通用。HoYoLAB 官方确认有角色详情/角色总览及分享图片能力，但这不是官方面向第三方开发者的稳定 API 承诺。[S8]

## 字段矩阵

“有”表示文档/模型存在，不表示本次对真实账号实测成功。“全量详情”指允许访问的角色列表对应详情，不是背包所有未装备物品。

| 字段 | 战绩角色列表 | 战绩角色详情 | Enka 展柜详情 | 实际助演名单 |
|---|---|---|---|---|
| 拥有角色 ID / 名称 | 有 | 列表决定查询范围 | 只有展柜角色 | 未发现自动接口证据 |
| 等级、命座 | 有 | 有 | 有 | 用户确认名单后再补配装 |
| 当前武器及等级、精炼 | 有 | 有，另含突破、主副属性 | 有，精炼编码为 0–4 | 不能拿好友展柜直接证明当前助演配装 |
| 天赋/技能等级 | 列表模型没有 | skills 含等级、解锁状态 | skillLevelMap | 缺失则手动补关键天赋 |
| 装备圣遗物套装、等级 | 列表模型没有 | 有 | 有 | 缺失则游戏内核对 |
| 圣遗物主、副词条 | 列表模型没有 | 有，含属性值与次数 | 有 | 不应从角色名或等级猜测 |
| 面板属性 | 列表模型没有 | 多组属性字段 | fightPropMap | 不等于实战伤害 |
| 未装备武器/圣遗物库存 | 没有此证据 | 没有此证据 | 没有 | 不纳入已确认能力 |
| 好友关系、当前助演选择与借用资格 | 没有此证据 | 没有此证据 | 没有此证据 | 用户在游戏内确认 |

字段依据是 genshin.py 的 `PartialCharacter`、`CharacterWeapon`、`GenshinDetailCharacter`、`DetailArtifact`、`CharacterSkill` 和 Enka 数据结构。[S2][S6] 必须区分列表与详情：调用 `get_genshin_characters` 并不等于拿到了天赋和圣遗物词条。不同来源的等级编码也不能原样混用；例如 Enka 圣遗物 level 为 1–21。[S1][S6]

## 授权与新鲜度

genshin.py 文档以登录 cookies 为主要身份验证方式，并展示浏览器会话、登录流程等集成方式。源码还包含不同地区请求处理及 cookie 更新机制。这些是已有工具能力，不是建议让用户把 cookie 发到聊天或提交仓库，也不能描述成已确认有官方 OAuth 授权接口。若后来选定该路径，应由本人在本机明确授权，并单独验证对应地区、账号绑定、会话更新和失败行为；本次不实施登录。[S3][S4]

Enka UID 响应有 `ttl`，过期前重复调用仍是缓存；保存配装则可能长期不更新。战绩字段模型没有为每一件装备提供可据以保证实时性的更新时间，也未从所查官方材料得到数据同步 SLA。因此应保存来源、抓取时间及“游戏内最近确认时间”，换装备/升级后刷新并核对；不要把抓取成功时间当成游戏状态更新时间。[S2][S5]

## 助演：历史借过不等于现在能借

genshin.py 的 `role_combat` 是剧诗战绩读取；模型把出战角色区分 NORMAL/TRIAL/SUPPORT，有等级、幕信息和统计。`rent_cnt` 描述助演帮助其他玩家的次数；它不是好友可借角色数组。检查当前 client 实现未找到好友助演候选枚举方法，Enka 文档同样没有该能力。[S1][S7]

HoYoverse 开发者介绍过游戏内助演记录功能，用来查看朋友借用支援角色；这只能证明游戏存在相关 UI，不能推出第三方可读取当前可借名单。[S9] 本次结论是“未找到并验证”，不是证明世界上不存在其他接口。

MVP 对缺口的最小补充建议：让本人从当期游戏助演界面确认候选角色、来源好友标识、可借状态及看到的配装，记录核对时间；仅当这些字段缺失时补填。朋友的公开展柜可作为配装参考，必须保留“未核对为当前助演”的状态。不要索取朋友登录凭据，也不要把公开强角色自动纳入可用池。

## 配装数据不等于战斗能力

上述接口提供角色、装备和部分战绩，不提供可直接套用于本期敌人、祝福、队友、轮转和本人操作的统一战力。天赋/词条完整也不能证明某队能稳定通关。建议只对无法由数据解释的缺口补充本人熟练度、已验证可用队伍及失败原因，并用实际通关表现验证推荐；不要先制造一个看似精确的战力分数。这是产品建模推论，不是接口已有输出。[S2][S6][S7]

## 研究完成与后续验收的边界

本问题已得到足够的输入范围与缺口结论，可供 MVP 定义使用。尚未证明的部分应成为选定数据路径后的验收条件，而不是当前阻塞全部产品研究：本人所属服务器的一次明确授权采样；拥有角色数对照；天赋/命座修正口径；换装后延迟；关闭公开详情和会话失效行为；助演名单及配装是否与游戏内一致。Enka 中国服各渠道支持仍保留为未验证项。当前不选择实现栈，不承诺自动拉取可借好友池。
