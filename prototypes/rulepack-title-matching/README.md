# 规则包与标题匹配原型（可抛弃）

对应票：[验证当期规则包的版本管理与标题匹配](https://github.com/HaotongCheng/BetterTheater/issues/17)。
这是决策材料，不是产品架构。阈值在同一批用例上调过，没有留出集；真实画面只有 4 张截图。

## 运行

```powershell
py -3.11 import_bwiki.py --inject demo.html   # BWIKI 快照 -> rulepack.json，并注入演示页
py -3.11 check_rulepack.py rulepack.json      # 结构校验 + 同名报告 + 核验状态
```

然后双击 `demo.html`（单文件，无需服务器）。页面上半是状态，中间是自由操作，下面是 10 个引导场景。

BWIKI 快照从主检出的 `docs/research/sources/bwiki-2026-09-17/`（未入库）读取，可用环境变量 `BT_SOURCES` 改路径。
`rulepack.json` 是导入产物，已提交，便于不跑脚本也能看；重跑会重写 `imported_at`。

报告：[`docs/research/rulepack-title-matching-2026-10-01.md`](../../docs/research/rulepack-title-matching-2026-10-01.md)。

## 文件

- `import_bwiki.py`：快照 HTML → 候选规则包。每棵祝福树按固定表形解析成 9 个节点（“进阶”按父分支各一个）；神秘收获按 名称/内容 两列表；“加强历史”里的表归到 `legacy-pre-YYYY-MM` 规则集。记录来源 revision、SHA-256、抓取日期、清洗规则，再合并 `verification.json`。
- `verification.json`：人工核验登记（条目 id → 截图证据 → 核验了哪些字段）。只登记画面上直接看到的，目前 5 条。
- `check_rulepack.py`：结构校验（身份唯一、树形完整、父子路径一致、规则集已登记、神秘收获标题唯一），同名报告，`--diff` 跨版本按身份比对并列出核验失效的条目。
- `rulepack.json`：导入结果（4 个规则集、23 棵树 / 207 节点、38 条神秘收获）。
- `demo.html`：单文件逻辑原型。`RuleMatch` 模块不碰 DOM，可整体搬走；页面外壳可抛弃。

## 规则身份

- 祝福：`规则集 / 反应族 / 等级 / 路径`，路径 L1 空、L2/L3 为 `1|2`、L4 为 `1A|1B|2A|2B`。标题与文字是证据，不是主键。
- 神秘收获：`规则集 / boon / 标题`（同一规则集内标题唯一，由校验保证）。
- 实例（神秘收获）：规则身份 + 实例参数（随机目标等，画面未显示则记“未知”）+ 获得幕次 + 状态（生效中/已结算/本幕已结束/已消费）。

## 匹配顺序

1. 标题精确命中（归一化“·”与空白）；命不中 → 看其他规则集：在 → “矛盾：版本漂移”，不在 → “未知”，相近标题只作提示。
2. 反应族、等级一致性；不一致 → “矛盾”。等级 0 → 未解锁。
3. 有摘要时算整体覆盖率（画面文字的二字片段有多少出现在候选节点及其祖先的文字里）；低于 35% → “矛盾：文字不符”。
4. 仍多候选时，只看“不是所有候选共有”的片段；领先者 ≥ 30% 且领先 ≥ 25 点 → 命中，否则 → “多候选”。
